# Data Model

## Entity-Relationship Diagram

```
ResearchSession
  │  id (PK, UUID)
  │  question (Text)
  │  status (String)
  │  error_message (Text, nullable)
  │  created_at, updated_at (DateTime)
  │
  ├──< SubQuestion (session_id FK)
  │      id (PK, UUID)
  │      session_id (FK → ResearchSession)
  │      question (Text)
  │      research_intent (Text)
  │      status (String)
  │      created_at
  │
  │    ├──< Source (sub_question_id FK)
  │           id (PK, UUID)
  │           sub_question_id (FK → SubQuestion)
  │           url (Text)
  │           title (Text)
  │           domain (String)
  │           source_type (String: web|wikipedia|api)
  │           publication_date (String, nullable)
  │           retrieved_at (DateTime)
  │           raw_content (Text)
  │           cleaned_content (Text)
  │           word_count (Integer)
  │           reliability_score (Float 0.0-1.0)
  │
  │         ├──< Finding (source_id FK)
  │                id (PK, UUID)
  │                source_id (FK → Source)
  │                text (Text)
  │                classification (String: supporting|contradicting|emerging|uncertain)
  │                confidence (Float 0.0-1.0)
  │                created_at
  │
  │              ├── Contradiction (finding_a_id, finding_b_id FK)
  │              │    id (PK, UUID)
  │              │    finding_a_id (FK → Finding)
  │              │    finding_b_id (FK → Finding)
  │              │    description (Text)
  │              │    severity (String: low|medium|high)
  │              │    confidence (Float 0.0-1.0)
  │              │    created_at
  │
  └──── Conclusion (session_id FK)
         id (PK, UUID)
         session_id (FK → ResearchSession, unique)
         text (Text)
         confidence (Float 0.0-1.0)
         key_points (JSON → List[str])
         limitations (JSON → List[str])
         created_at

         ├── ConclusionFinding (M2M link)
               conclusion_id (FK → Conclusion)
               finding_id (FK → Finding)
               relationship_type (String: supporting|contradicting)
```

## Table Descriptions

### `research_sessions`
The root entity. One per research question. Status tracks pipeline progress.

**Status values**: `pending → decomposing → searching → extracting → analyzing → synthesizing → completed | failed`

### `sub_questions`
Generated by the decomposer. Each represents a targeted search vector for the original question. 3-5 per session.

### `sources`
Real web pages and Wikipedia articles retrieved during research. Each source is linked to the sub-question that triggered it.

**reliability_score** is computed heuristically:
- Wikipedia → 0.9
- `.gov` domains → 0.85
- `.edu` domains → 0.8
- >500 words → +0.1 bonus
- <200 words → penalty

### `findings`
Atomic knowledge claims extracted from source text by the LLM. Each finding has:
- **classification**: `supporting` (supports common knowledge), `contradicting` (conflicts with other findings), `emerging` (new/novel finding), `uncertain` (unclear)
- **confidence**: 0.0-1.0 LLM-estimated confidence in the finding

### `contradictions`
Pairs of findings where the LLM detected genuine conflict. Always links two findings from the same session.

**severity**: `low` (minor difference), `medium` (significant disagreement), `high` (direct opposition)

### `conclusions`
One per completed session. The final synthesized answer.

**key_points** and **limitations** are stored as JSON arrays in Text columns (for SQLite compatibility).

### `conclusion_findings`
Many-to-many join table. Links a conclusion to the specific findings that support or contradict it.
This is the **traceability chain** — from conclusion → finding → source → URL.

## ChromaDB Collections

### `research_findings`
All findings are embedded here when created. Metadata stored:
- `finding_id`
- `source_id`
- `classification`
- `confidence`

Used by `POST /query` for semantic search.

## Key Constraints

| Table | Unique Constraints |
|---|---|
| `research_sessions` | `id` |
| `sub_questions` | `id`, `(session_id, question)` |
| `conclusions` | `id`, `session_id` (one conclusion per session) |
| `conclusion_findings` | `(conclusion_id, finding_id)` |
